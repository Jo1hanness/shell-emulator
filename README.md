# Shell Emulator

Эмулятор командной строки UNIX с графическим интерфейсом (Java Swing).
Вариант 15, ПЗ №1 по дисциплине «Конфигурационное управление».

## Требования
JDK 8 или новее.

## Запуск
```
./run.sh [--vfs PATH] [--script PATH]
```
- `--vfs PATH` — путь к ZIP-архиву с виртуальной файловой системой
- `--script PATH` — путь к стартовому скрипту

## Этап 1. REPL
- окно с именем VFS в заголовке
- раскрытие переменных окружения ($HOME)
- команды-заглушки ls, cd; команда exit
- сообщения об ошибках: неизвестная команда, неверные аргументы

## Этап 2. Конфигурация
- параметры командной строки `--vfs` и `--script`
- при запуске выводятся все заданные параметры (`[debug] ...`)
- стартовый скрипт выполняется построчно; на экран выводятся и команда, и её результат, как в диалоге
- строки, начинающиеся с `#`, и пустые строки — комментарии
- при первой ошибке выполнение скрипта останавливается

Тесты: `tests/stage2/run_*.sh` — запуск эмулятора с разными параметрами.

## Этап 3. VFS
- VFS загружается из ZIP-архива (`--vfs`) целиком в память; архив не распаковывается и не изменяется
- содержимое файлов хранится в base64 (`VfsNode`), поэтому поддерживаются и двоичные данные
- ошибки загрузки: файл не найден, файл не является ZIP-архивом — эмулятор сообщает об ошибке и работает с пустой VFS
- приглашение показывает текущий каталог VFS (`/home/user $`)

Тестовые VFS лежат в `tests/vfs/` (генерируются скриптом `tests/vfs/make_vfs.py`):
- `minimal.zip` — один файл
- `deep.zip` — несколько уровней вложенности (до 5), пустой каталог, двоичный файл
- `empty.zip` — пустой архив, `broken.zip` — не ZIP

Тесты: `tests/stage3/run_*.sh`, общий скрипт `tests/stage3/all.txt` проверяет этапы 1–3.
